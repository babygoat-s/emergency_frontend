# 119 긴급 음성 분석기

`emergency_backend`의 FastAPI API에 연결하는 Vite + React 반응형 프런트엔드입니다. 파일 업로드·실시간 녹음·현재 분석 결과를 한 화면에서 사용합니다. DB와 기록 API가 없어 분석 기록 메뉴와 자동 저장은 없습니다.

현재는 **요약·긴급도 AI 보류**입니다. 서버의 개인정보 설정을 확인한 후 음성·증상·로컬 매뉴얼 질문만 분석합니다. 요약·긴급도 카드와 해당 다운로드 항목은 숨깁니다.

## 실행

화면은 `#0E0F12` 배경의 다크 대시보드입니다. 데스크톱에서는 화자별 전사를 왼쪽, 긴급도·증상·후속 질문을 오른쪽에 표시하며 좁은 화면에서는 세로로 배치합니다. Pretendard 가변 글꼴은 `public/fonts`에서 로컬로 제공하고, 아이콘은 `lucide-react`를 사용합니다. 글꼴 라이선스는 `public/fonts/Pretendard-LICENSE.txt`에 포함되어 있습니다.

백엔드의 PDF 인덱싱과 `RAG_ENABLED=true` 설정 후 **대화 입력**을 사용할 수 있습니다. 신고자·상담원 접두어로 대화를 입력하고 추가 발화를 붙인 후 다시 추천받으세요. 실시간 음성과 파일 분석에 로컬 상태와 원문 분기에 따른 매뉴얼 질문을 표시합니다. 근거는 SOP 501의 인쇄 쪽수와 상담 매뉴얼의 PDF 쪽수를 문서명과 함께 일반 텍스트로 표시합니다. PDF 링크와 질문 ID는 화면·다운로드에서 제외합니다. 오래된 매뉴얼 안내는 페이지 맨 하단에서 한 번 표시합니다. 설치와 데이터 구조는 백엔드의 `docs/RAG.md`에 있습니다.

백엔드 터미널:

```powershell
cd C:\Users\lemon\Desktop\emergency_backend
.\run.ps1
```

프런트엔드 터미널:

```powershell
cd C:\Users\lemon\Desktop\emergency_frontend

```

브라우저에서 <http://localhost:5173>에 접속합니다. 의존성이 설치되어 있으면 `npm install`은 생략할 수 있습니다. Vite는 `/api`의 HTTP와 WebSocket을 기본 백엔드 `http://127.0.0.1:8000`으로 프록시합니다.

전사에는 백엔드의 로컬 Whisper 실행 환경이 필요합니다. 현재 음성·증상·매뉴얼 질문에는 외부 API 키가 필요하지 않습니다. 설정을 바꾸면 백엔드를 재시작하세요. 서버가 실행 중이면 고정 예시를 볼 수 있습니다. 상태 표시는 서버 응답과 키 입력 여부를 보여 줍니다.

## 분석 결과의 의미

Whisper가 음성을 텍스트로 변환하고, 백엔드에 연결한 KoELECTRA가 증상을 분류합니다. **고열, 구토·오심, 두통, 복통, 어지러움, 열상, 전신쇠약, 호흡곤란**을 대상으로 하며 같은 목록을 화면의 **분류할 수 있는 증상** 카드에서 볼 수 있습니다. 현재는 로컬 분류기 결과를 사용하며 외부 LLM이 증상 분류를 대신하지 않습니다.

RAG 모드에서는 로컬 임베딩·Chroma와 원문 분기를 이용해 질문을 선택합니다. 팔 마비 보고에는 관련 프로토콜의 발음·감각·발생 시각 질문을 적용하고, 확인된 정보는 재질문하지 않습니다. 기본 의식·정상 호흡 정보가 필요하면 먼저 확인합니다.

실시간 입력은 마이크, PC·통화 오디오, 선택한 파일 직접 입력을 지원합니다. PC 입력은 공유 대상의 소리만 전사하며 마이크를 혼합하지 않습니다. 파일을 스피커로 재생해 마이크로 녹음할 필요가 없습니다. 마이크·PC 녹음 원음은 브라우저 메모리의 재생기로 확인할 수 있습니다. 종료 시 반복 응답의 한 구간만 로컬 모델로 재검토할 수 있어 최종 결과가 늦어질 수 있습니다. 원음을 확인하지 못한 구간은 증상 근거로 사용하지 않습니다.

추후 LLM을 활성화하면 별도의 개인정보 정책 검토가 필요합니다. 개인정보 설정을 제공하지 않는 구버전 서버에는 예시 외 분석을 보내지 않습니다.

## 기능

- 파일 업로드: 드래그 앤 드롭·파일 선택·미리 듣기·언어 선택·분석 취소.
- 파일 검사: 서버 설정의 확장자·용량과 읽을 수 있는 재생 시간 검사. 최종 디코딩·검증은 백엔드에서 수행.
- 실시간 녹음: AudioWorklet으로 16 kHz, 모노, PCM16 little-endian을 100ms 단위 전송. 종료 시 마지막 프레임과 최종 분석 처리.
- 결과: 전사·시간 구간·증상과 매뉴얼 질문. 요약·긴급도는 설정에 따라 표시. 현재 결과를 UTF-8 텍스트로 다운로드.
- 예시: 고열·구토·두통이 포함된 가상 신고의 고정 결과를 조회. 미리보기 문장과 증상 태그도 서버에서 제공.
- 사용 안내: 파일·마이크 사용 절차, 서버 상태와 처리 지연 안내.

REST와 WebSocket의 서버 오류 메시지를 화면에 그대로 표시하지 않습니다. 입력 오류·요청 과다·시간 초과 등은 프런트엔드의 고정 문구로 안내하고 나머지는 일반 분석 실패 문구로 표시합니다. 상세 HTTP 상태·내부 오류 코드·키 설정·모델 요청 상세는 사용자 화면과 다운로드에 포함하지 않습니다. 개발자 진단은 백엔드 README의 `check_gemini.py`를 사용합니다.

현재 결과는 React 메모리에만 존재해 새로고침하면 사라집니다. 음성은 분석을 위해 백엔드로 전송되며 전사 등은 백엔드가 구성한 Gemini API로 전송될 수 있습니다. 필요한 결과는 새로고침 전에 직접 다운로드하세요.

## 연결 API

| 기능 | HTTP | Path |
| --- | --- | --- |
| 서버 상태 | GET | `/api/v1/health` |
| 분석 설정 | GET | `/api/v1/analysis/config` |
| 파일 전체 분석 | POST | `/api/v1/analysis/file` |
| 고정 예시 | GET | `/api/v1/analysis/example` |
| 실시간 분석 | WebSocket | `/api/v1/analysis/realtime` |

요청·응답 계약은 백엔드 `docs/API.md`를 참고하세요. 실시간은 `start → ready → PCM binary → finish → finished` 순서입니다. 전사·증상·상황 분석의 `sequence`를 따로 관리하며, 최신 Gemini 결과를 기다리는 동안 기본 질문을 표시합니다. 파일·예시 분석 완료 시 결과 영역으로 이동합니다.

## 환경 설정과 배포

필요한 경우 `.env.example`을 `.env.local`로 복사해 변경합니다.

```dotenv
API_PROXY_TARGET=http://127.0.0.1:8000
# 별도 도메인 배포 시 서버 origin만 지정 (/api/v1 제외).
# VITE_API_BASE_URL=https://your-api.example.com
```

- 개발과 `npm run preview`는 Vite 프록시를 사용합니다.
- Vercel 프런트엔드 프로젝트에 `BE_API_BASE_URL`을 설정하고 다시 배포하면 HTTP와 WebSocket이 해당 HTTPS origin을 사용합니다. Cloud Run에 직접 연결할 때는 백엔드의 Google 인증을 켜고 동일한 웹 클라이언트 ID를 `GOOGLE_CLIENT_ID`에 지정하세요. 빌드 결과에 포함되는 값에는 자격 증명을 넣지 마세요. 기존 `VITE_GOOGLE_OAUTH_CLIENT_ID`와 `VITE_API_BASE_URL`이 함께 설정돼 있으면 각 설정에서 우선합니다.
- 정적 배포에서 두 환경변수를 비워 두면 같은 origin의 `/api`를 사용합니다. 이 경우 운영 서버가 HTTP와 WebSocket을 중계해야 합니다. 로컬 Vite는 `API_PROXY_TARGET`, `BE_API_BASE_URL`, `http://127.0.0.1:8000` 순으로 프록시 대상을 선택합니다.
- 다른 origin에 직접 연결하면 백엔드 `CORS_ORIGINS`에 프런트엔드 origin을 허용해야 합니다. WebSocket도 같은 정책을 따릅니다.
- 마이크는 localhost 또는 HTTPS에서 사용합니다. 모바일 기기 접속에는 HTTPS가 필요합니다.
- HTTPS 프런트엔드에서는 HTTPS/WSS 백엔드를 사용하세요.
- `VITE_` 변수는 브라우저에 노출됩니다. Gemini 키는 백엔드에서만 관리하세요.
- Noto Sans KR 웹폰트에 연결하지 못하면 시스템 한글 글꼴을 사용합니다.

긴급도는 LLM 응답만 표시합니다. 모델 응답 전에는 분석 대기, 연결·검증 실패는 분석 미완료, LLM이 정보 부족으로 보류한 경우는 판단 보류로 구분합니다. 음성 상태 추정 패널과 관련 데이터 경로는 제거했습니다.
### 상담원 음성 등록

**실시간 녹음** 탭에서 **상담원 음성 등록**을 선택해 안내 문장 세 개를 읽고 녹음합니다. 미리 들어본 뒤 **샘플 저장**을 누르면 백엔드의 발화 구간 검사를 거쳐 이 브라우저에 음성이 저장됩니다. Google 로그인 환경에서는 로그인 계정별로 재사용하며, 같은 브라우저에서 다시 열어도 실시간 분석을 시작할 때 자동으로 적용됩니다. **음성 삭제**를 누르면 저장된 샘플을 제거할 수 있습니다.

샘플은 백엔드의 Wav2Vec2 등록 단계에만 전송합니다. 실제 통화 음성과 분리해 전사와 LLM 입력에는 포함하지 않습니다.
